SportsBettingTrackerApp - Dev Session Summary 2

Date: April 14, 2026

1. Dapper vs EF Core

The project uses Dapper, matching the pattern from MVCIntroWebsite. This means:

  • Raw SQL queries are written manually
  • No migrations or DbContext needed
  • Database tables are managed directly in MySQL
  • Packages required: Dapper and MySql.Data

2. MySQL Table

Table created directly in MySQL:

CREATE TABLE UserLoginInformation (
  user_id    INT AUTO_INCREMENT PRIMARY KEY,
  username   VARCHAR(50)  NOT NULL UNIQUE,
  email      VARCHAR(100) NOT NULL UNIQUE,
  passwordHash VARCHAR(255) NOT NULL
);
Note: created_at and last_login columns were dropped. password_hash was renamed to passwordHash to match C# property names.

3. Updated UserModel.cs

Updated to match the MySQL table with PascalCase properties. The private parameterless constructor is required for Dapper to materialize objects when reading from the database.

namespace SportsBettingTrackerApp.Models;

public class UserModel
{
    public int UserId { get; set; }
    public string Username { get; set; }
    public string Email { get; set; }
    public string PasswordHash { get; set; }

    public UserModel(string username, string email, string passwordHash)
    {
        Username = username;
        Email = email;
        PasswordHash = passwordHash;
    }

    private UserModel() { }
}

5. Data Layer

IUserLoginInformationRepository.cs

using SportsBettingTrackerApp.Models;

namespace SportsBettingTrackerApp.Data;

public interface IUserLoginInformationRepository
{
    UserModel GetUserByEmail(string email);
    void InsertUser(UserModel user);
}

UserLoginInformationRepository.cs

using System.Data;
using Dapper;
using SportsBettingTrackerApp.Models;

namespace SportsBettingTrackerApp.Data;

public class UserLoginInformationRepository : IUserLoginInformationRepository
{
    private readonly IDbConnection _connection;

    public UserLoginInformationRepository(IDbConnection connection)
    {
        _connection = connection;
    }

    public UserModel GetUserByEmail(string email)
    {
        return _connection.QuerySingleOrDefault<UserModel>(
            "SELECT * FROM UserLoginInformation WHERE email = @email",
            new { email });
    }

    public void InsertUser(UserModel user)
    {
        _connection.Execute(
            "INSERT INTO UserLoginInformation (username, email, passwordHash) VALUES (@username, @email, @passwordHash)",
            new { username = user.Username, email = user.Email, passwordHash = user.PasswordHash });
    }
}

9. AccountController.cs

Key concepts:

  • Dependency injection — the repository is injected via the constructor so the controller can access the database
  • [HttpGet] — explicitly marks actions as GET requests (optional but recommended when paired with POST actions)
  • BCrypt — used to hash passwords on register and verify them on login
  • QuerySingleOrDefault — returns null if no user is found rather than throwing an exception
using Microsoft.AspNetCore.Mvc;
using SportsBettingTrackerApp.Data;
using SportsBettingTrackerApp.Models;

namespace SportsBettingTrackerApp.Controllers;

public class AccountController : Controller
{
    private readonly IUserLoginInformationRepository _userRepository;

    public AccountController(IUserLoginInformationRepository userRepository)
    {
        _userRepository = userRepository;
    }

    [HttpGet]
    public IActionResult Login() => View();

    [HttpPost]
    public IActionResult Login(LoginViewModel model)
    {
        var user = _userRepository.GetUserByEmail(model.Email);
        if (user == null)
            return View(model);

        bool isValidPassword = BCrypt.Net.BCrypt.Verify(model.Password, user.PasswordHash);
        if (!isValidPassword)
            return View(model);

        return RedirectToAction("Index", "Home");
    }

    [HttpGet]
    public IActionResult SignUp() => View();

    [HttpPost]
    public IActionResult SignUp(RegisterViewModel model)
    {
        var passwordHash = BCrypt.Net.BCrypt.HashPassword(model.Password);
        var user = new UserModel(model.UserName, model.Email, passwordHash);
        _userRepository.InsertUser(user);
        return RedirectToAction("Login");
    }
}

10. Key Concepts Covered

Dependency Injection

A way of giving an object what it needs to do its job, rather than having it create those things itself. ASP.NET reads the constructor, sees what's needed, and automatically provides it based on what's registered in Program.cs.

  • Controller depends on the repository
  • Repository depends on the database connection
  • Both are registered in Program.cs and provided automatically

Why ViewModels Can't Have Custom Constructors

ASP.NET's model binder creates the object using a parameterless constructor, then sets each property from the form fields. If only a custom constructor exists, the binder throws an error. Database entities (like UserModel) are different — Dapper handles them and can work with custom constructors as long as a private parameterless constructor is also present.

BCrypt Password Hashing

// On register — hash the plain text password
string hash = BCrypt.Net.BCrypt.HashPassword(model.Password);

// On login — verify plain text against stored hash
bool isValid = BCrypt.Net.BCrypt.Verify(model.Password, user.PasswordHash);
