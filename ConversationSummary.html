2. Models Created

UserModel.cs

Represents the database entity matching the UserLoginInformation MySQL table. Uses a custom constructor (valid for EF/Dapper entities) and a private parameterless constructor for database materialization.

namespace SportsBettingTrackerApp.Models;

public class UserModel
{
    public int user_id { get; set; }
    public string username { get; set; }
    public string email { get; set; }
    public string password_hash { get; set; }

    public UserModel(string username, string email, string passwordHash)
    {
        this.username = username;
        this.email = email;
        this.password_hash = passwordHash;
    }

    private UserModel() { }
}

3. Key Concepts Discussed

Why string.Empty / required / nullable?

With <Nullable>enable</Nullable> in the .csproj, the compiler warns when non-nullable strings are uninitialized. Three options:

  • = string.Empty — gives a default value
  • string? Property — marks it explicitly nullable
  • required string Property — C# 11 keyword, must be set at construction (no using needed)

Custom Constructors — When to Use

  • Database entities (UserModel) — custom constructor is fine. Add a private UserModel() {} for EF/Dapper to materialize objects from the DB.
  • ViewModels (LoginViewModel, RegisterViewModel) — do NOT use custom constructors. ASP.NET's model binder needs a parameterless constructor to bind form data.

PasswordHash vs Password

Passwords are never stored in plain text. They are run through a hashing algorithm (e.g. BCrypt) and the result is stored. On login, the entered password is hashed and compared to the stored hash.

// On register
string hash = BCrypt.Net.BCrypt.HashPassword(plainTextPassword);

// On login
bool valid = BCrypt.Net.BCrypt.Verify(plainTextPassword, storedHash);

Dapper vs EF Core

  • Dapper — lightweight, you write raw SQL. No migrations or DbContext needed. Used in this project.
  • EF Core — heavier, generates SQL for you. Requires DbContext, DbSet, and migrations.

This project uses Dapper + MySql.Data, matching the pattern from MVCIntroWebsite.

5. Data Layer

IUserLoginInformationRepository.cs

using SportsBettingTrackerApp.Models;

namespace SportsBettingTrackerApp.Data;

public interface IUserLoginInformationRepository
{
    UserModel GetUserByEmail(string email);
    void InsertUser(UserModel user);
}

UserLoginInformationRepository.cs

using System.Data;
using Dapper;
using SportsBettingTrackerApp.Models;

namespace SportsBettingTrackerApp.Data;

public class UserLoginInformationRepository : IUserLoginInformationRepository
{
    private readonly IDbConnection _connection;

    public UserLoginInformationRepository(IDbConnection connection)
    {
        _connection = connection;
    }

    public UserModel GetUserByEmail(string email)
    {
        return _connection.QuerySingleOrDefault<UserModel>(
            "SELECT * FROM UserLoginInformation WHERE email = @email",
            new { email });
    }

    public void InsertUser(UserModel user)
    {
        _connection.Execute(
            "INSERT INTO UserLoginInformation (username, email, password_hash) VALUES (@username, @email, @passwordHash)",
            new { username = user.username, email = user.email, passwordHash = user.password_hash });
    }
}
